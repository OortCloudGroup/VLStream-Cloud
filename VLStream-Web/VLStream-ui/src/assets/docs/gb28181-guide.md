# VLStream 国标接入与多上级对接经验

本说明结合系统使用说明 PDF、2026-09-12 双上级复盘及 2026-09-13 无人值守验收整理。所有示例地址和编号均为示意，不能直接作为现场配置使用；不包含现场账号和密码。

平台支持对接多个上级，分别维护注册参数、共享映射及授权。原始资料中的双上级是一个现场案例；下文 A、B 仅用于演示差异，新增其他上级时沿用相同流程。

## 1. 设备接入本平台

摄像机 / NVR → VLStream → 多个上级平台（A / B / …）。

在设备 GB28181 配置页填写 VLStream 的服务信息：

| 设备端字段 | 示例 | 获取方式 |
| --- | --- | --- |
| SIP 服务器编号 | 34020000002000000002 | 国标设备页 → 国标服务信息 → 编号 |
| SIP 服务器域 | 3402000000 | 同上 → 域 |
| SIP 服务器 IP | 192.0.2.10 | 选择设备能访问的一个本机地址，不能填完整 IP 列表 |
| SIP 服务器端口 | 8116 | 同上 → 实际端口，并确认 UDP/TCP |
| 认证密码 | 按现场配置 | 国标 SIP 密码，与管理页面登录密码不同 |

设备自身编号和视频通道编号另行配置，不能直接使用 SIP 服务器编号。接入后核对注册、心跳、目录和本地视频解码。

## 2. 配置多个上级平台（以 A、B 为例）

| 表单字段 | 上级 A 示例 | 上级 B 示例 | 说明 |
| --- | --- | --- | --- |
| 名称 | 指挥平台 A | 指挥平台 B | 独立配置 |
| SIP服务国标编码 | 34020000002000000001 | 34030000002000000001 | 上级身份 |
| SIP服务国标域 | 3402000000 | 3403000000 | 以上级提供值为准 |
| SIP服务IP | 192.0.2.20 | 192.0.2.30 | 上级信令 IP |
| SIP服务端口 | 5060 | 5061 | 上级实际监听端口 |
| 设备国标编号 | 34020000002000000002 | 34020000002000000002 | 本平台接入身份，分别取得上级授权 |
| 本地IP | 192.0.2.10 | 192.0.2.10 | 与上级相通的本机网卡 |
| 本地端口 | 8116 | 8116 | 来自本机配置，只读 |
| SIP认证用户名/密码 | 由 A 分配 | 由 B 分配 | 不填写示例密码 |
| 注册周期(秒) | 3600 | 按 B 实际策略填写 | 成功应答有效期可能短于请求值 |
| 心跳周期(秒) | 60 | 60 | 以各上级要求为准 |
| 信令传输 | UDP | UDP | 信令和媒体传输方式分别确认 |
| 字符集 | GB2312 | UTF-8 | 与对端保持一致 |

注册有效期是 SIP 的 Expires，不是 Web token。现场曾将有效期 300 秒的上级配置为 240 秒续注册、60 秒心跳；不要把这一参数应用到所有上级。当前源码补充按实际有效期提前续注册，使用该能力需要部署包含此变更的后端。

## 3. 共享视频编号

| 原始通道示例 | 上级 A 共享编号 | 上级 B 共享编号 |
| --- | --- | --- |
| 设备甲：34020000001310000001 | 34020000001310000001 | 34030000001310000001 |
| 设备乙：34020000001310000001 | 34020000001310000002 | 34030000001310000002 |

两台设备可能上报相同原始通道号，但向同一上级发布的共享编号必须唯一。视频共享编号不能与平台目录节点编号重合。变更后先取得上级号段与通道授权，再推送目录，由上级刷新缓存后按共享编号点播。

## 4. 最短排查顺序

1. 注册：同一事务的 REGISTER、401、鉴权 REGISTER、200/403；核对身份、用户名、密码、注册有效期和授权。
2. 目录：上级实际收到的共享编号及视频节点，是否重号、已授权。
3. 点播：INVITE 的目标共享编号；404 查映射，486/超时查源设备回流。
4. 信令与媒体：SIP IP 不一定等于媒体 IP；按 SDP 协商核对 UDP/TCP、RTP/RTCP、NAT、回程和实际出口端口。
5. 解码：接收到媒体不等于出画面。对照正常设备检查编码，必要时抓包和解码；现场 H.265 有效处理不代表所有 H.264 均不兼容。
6. 复验：本地逐路解码，各个已对接上级分别点播、停止并覆盖至少一次续注册。

固定 SIP 出口端口与固定 RTP 端口范围，需要部署端和网络端共同配置。每次视频会话可以在范围内分配不同端口。

## 5. 无人值守边界

开机恢复需要 BIOS 来电自动开机、操作系统启动 Docker、服务依赖就绪、健康巡检、业务状态重建、数据库备份及视频复验配合。默认 Compose 的退出重启策略不等于持续不健康自动修复。

现场文档中的每日 03:20 备份、保留 7 份、Redis tmpfs、systemd 服务和恢复脚本属于该现场交付，不能推定任何新部署已经启用。切换纯缓存 Redis 前必须完成布局迁移、位置队列处理及缓存丢失后的会话重建验收；保留原卷以便回滚。

正常重启不能替代物理断电验收；断电后无需按键开机、各个已对接上级恢复实播要在现场验证。无电、磁盘损坏和外部设备故障不能由本机应用保证恢复。


## 6. 对接经验记录

每次联调记录：场景及版本、问题现象、脱敏排查证据、处理方法、逐个上级的复验结果、适用范围与待确认项。

示例：某设备在特定上级有 RTP 但黑屏，检查媒体报文和解码结果后调整编码并复验。记录应保留具体设备与平台组合，供以后定位相似问题；不要把该组合的成功参数推广为所有平台的默认配置。
