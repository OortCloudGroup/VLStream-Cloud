# 云端智能：运行与维护

## 入口与范围

决策式 AI → 云端智能包含场景治理、任务配置、任务状态、智能分析。任务状态通过 `/task-status` 独立进入运行记录，支持状态筛选、执行详情、停止与关联事件。API 为 `/cloud-ai`，前端路由分别为 `/scene-governance`、`/algorithm-task`、`/intelligent-analysis-request`（部署时保留应用基础路径）。

场景定义“检测什么”：授权摄像机、固定模型版本、自有／公司免费 GPU、告警类别、置信度、抽帧频率、上报间隔及录像前后时长。每台摄像机执行全部选中模型，并复用该摄像机的一份解码输入。当前执行格式为可信的 YOLO 目标检测 PT，必须有类别映射且兼容已配置的运行环境；不自动下载替代模型，不降级 CPU，不提供收费算力开关机或计费。

任务定义“何时检测”。手工任务保存即提交，实际开始推理后计算运行时长；可提前停止。定时任务支持单次、每天、每周、跨午夜和有效期，时区固定 Asia/Shanghai。一次窗口只创建一轮；GPU 忙时排队，超过窗口结束时间记录跳过，不补跑、不延长、不抢占。

智能分析与主动安全共用事件及处置结果。默认保存告警前 5 秒、后 10 秒录像，可以在场景修改。缺少前段、断流或帧不足时显示实际时长和部分录像，不能将“有视频文件”视为证据完整。

## 系统边界

| 组件 | 职责 |
| --- | --- |
| VLS | 场景、任务、调度、运行快照、模型与 GPU 校验、远端执行协调、事件关联和证据归档 |
| WVP | 设备／通道的权威目录、用户及租户访问校验、取流授权、平台原生开流及会话释放 |
| GPU 执行器 | 收流、解码、CUDA 推理、逐路心跳、有限视频缓存、截图与录像、受控停止 |
| 对象存储 | 固定摘要的模型及事件证据；事件读取使用原有授权和短期媒体地址 |
| 现有事件系统 | single 使用本地主动安全；multi 使用 VLS 事件和 outbox；沿用反馈与工单入口 |

目录覆盖 VLStream、ONVIF、RTSP、ISUP、EHome、GB28181、大华、自定义。接入依据实际流能力；设备协议名称、在线标记或浏览器能播放均不足以证明 GPU 可收流。直接网络源由 GPU 解码，需要 SDK／平台开流的源在获得 GPU 后申请运行专属会话。国标及已有推流遵循媒体服务既有无读者生命周期，不能关闭其他播放／录像使用的共享流。

CameraRTC 播放器使用自有信令和 WebRTC。服务端先完成信令、ICE、媒体接收、解码，再把画面交给模型；不能把播放页面 URL 直接作为模型输入，也不需要保持用户浏览器打开。

## 部署条件

1. 按两项目 POM 使用匹配 JDK 构建。当前 VLS 是 Java 8。VLS、WVP 都必须部署包含云端智能接口的版本；只更新前端不能启用检测。
2. 由 Flyway 执行 VLS `V1_2_0_058__cloud_ai_scenes_tasks_runs.sql`、`V1_2_0_059__cloud_ai_active_safety_event_owner.sql`，以及 WVP `V1_2_16__cloud_ai_source_grants.sql`。已执行的迁移不得修改或重跑增量 SQL；059 用于将 single 的早期云端事件统一到本地主动安全权威。
3. 配置 VLS 的 `vlstream.wvp-device.base-url` 指向正确 WVP。保留现有受信服务通信、租户、身份、加密材料和存储配置，禁止用客户端传入的任意目标地址替代。
4. 对 CameraRTC，在 WVP 配置 `video.custom-availability.camera-rtc-signal-url` 为设备实际使用的信令服务地址。此值属于部署环境，不在仓库写入某台设备的地址。GPU 必须能完成该服务的信令和 ICE／媒体连接；仅 HTTP 页面可达不代表 WebRTC 可用。
5. GPU 需有有效的 SSH 身份、公钥校验、GPU UUID／索引、工作目录、CUDA 驱动及既有共享队列配置；界面健康检查通过后才能提交。当前入口只接受免费自有／公司资源。
6. GPU Python 需有 CUDA 可用的 PyTorch、OpenCV、Ultralytics **8.3.240**，以及 `cloudai/requirements-media.txt` 固定的 aiortc **1.14.0**、aiohttp **3.13.3**、av **16.1.0**。媒体依赖安装在检测专用环境，避免改变已有训练环境。执行器优先使用节点工作目录下 `.cloud-ai-runtime-v1/bin/python`，不存在则使用节点配置的 Python；启动前校验依赖，缺失即报告准备失败。
7. 模型需要归档、类别、版本、大小与 SHA-256，执行时再次检查。历史外部 PT 仅由运维逐个确认可信来源后登记 `vlstream.cloud-ai.trusted-models`，以 `tenant-id`、`model-id`、`source-node-id`、`sha256` 固定身份；不能因扩展名为 PT 就自动信任。普通页面用户不应获得修改该登记的能力。
8. 证据存储应可写、可读并通过大小／摘要校验；浏览器获取媒体沿用事件权限。远端工作目录和源授权材料应仅供运行账号使用，日志不得输出取流凭据或签名地址。

执行器脚本随应用资源发布到本次运行目录；不依赖手工长期运行一个浏览器或另开播放页。节点容量需按实际分辨率、模型和路数测试，界面允许的摄像机数量不等于该 GPU 的实时吞吐保证。

## 状态与操作

| 状态或操作 | 含义与处理 |
| --- | --- |
| 排队中 | 尚未获得物理 GPU，占用者可以是训练或其他检测；继续等待或停止本轮 |
| 准备中 | 校验环境、模型及视频源，尚未证明实际推理开始 |
| 运行中 | 执行器报告真实心跳、收帧和模型推理次数 |
| 部分异常 | 有摄像机／模型异常；查看分路状态，不能视为全部正常 |
| 状态待确认 | SSH、执行或归档结果未确认；保留原运行重试，不重复派发、不提前释放 GPU |
| 停止中 | 停止新推理，允许有限的告警后段录像和归档收尾 |
| 正常完成 | 达到实际时长／计划结束，组合完成、执行退出及归档得到确认 |
| 已停止 | 用户停止得到执行器退出确认；与正常完成区分 |
| 已跳过 | 尚未执行而计划窗口过期等原因；不会补跑 |
| 停用定时配置 | 阻止后续计划，不停止已经运行的检测；当前运行须另行停止 |

编辑场景不会改变已提交运行的冻结快照。任务配置和执行记录独立保留；引用中的场景不能直接删除，活动运行也不能通过删除记录来结束。历史事件保留当时的模型、摄像机和运行信息。

共享队列释放依赖进程退出、归档清单摘要、事件数量和逐事件确认。租约超时不等于远端已结束。原生推理／媒体调用长期阻塞时，独立看门狗退出执行器，后台仍须验证退出及处理归档。出现未知占用应修复连接并恢复原任务，不可直接删锁或另起一轮绕过互斥。

## 事件与权限

场景、任务、运行及异步执行固定可信租户和创建人。WVP 每次解析取流授权时重新校验设备／通道及用户范围；设备移除、授权撤销、归属或部门变化导致核验不再通过时停止继续使用。旧协议仅默认租户可见的既有边界不因此扩大。

single 模式以 `oort_task_event` 为唯一事件权威；multi 模式以 `vls_event_management` 与 outbox 为权威。`vls_cloud_ai_event` 保存云端来源和证据关联，不维护第二份独立的处置状态。截图可先展示，录像稍后回填同一事件；媒体回填不覆盖已经提交的反馈。重复接收通过稳定事件标识幂等处理。

“前往处置”打开主动安全的同一条事件，沿用既有反馈和工单流程。多租户外部上报、视觉复核、自动建单及 Flowable 各分支取决于对应环境和流程配置，须分别验收，不能从单租户检测成功推断全部外部流程成功。

## 验收边界

逐环境检查：GPU 实际收帧与推理、每个摄像机／模型组合、告警图片和实际录像时长、同事件处置同步、运行提前停止／到时结束、共享资源排队和到期跳过。日／周配置还需核对有效期、跨午夜、下次时间以及重复扫描不产生重复运行。

单元测试、模拟源和合成视频只证明其覆盖逻辑；其他原生协议硬件、特殊编码、网络隔离、多租户外部服务以及完整故障恢复需要各自实机验收。保留失败原因与部分录像事实，不以成功编译、在线状态或存在输出文件代替业务闭环。
