# 公司算力统一平台管理

## 当前供给与管理入口

公司免费 GPU 和官方 AutoDL 实例由统一平台能力中心的“算力”菜单维护，管理界面位于相邻 `oort_pc_web`，持久化及授权位于 `apaas-deployment-service`。VLS 通过 `POST /compute/v1/executionCatalog` 读取执行目录。普通算力列表提供公开摘要，系统管理员可维护规格、连接、凭据引用和执行环境。管理权限由后台核验，普通租户管理员身份本身不授予全局算力写入权。

平台资源 UID、稳定业务编码和 VLS 调度 ID 分开保存。原资源继续使用 `-173`、`-99`、`-6000`，经核验的历史别名以十进制字符串穿过浏览器接口。新资源由后台分配负数调度 ID。编辑保留身份，逻辑删除保留版本和历史引用；管理员可在“显示已删除”中恢复原记录，恢复后为停用和隐藏状态。

每项资源维护 GPU、CPU、内存、磁盘、驱动、CUDA、规格来源与观察日期。规格用于展示，环境检查和实际运行证据决定可调度状态。平台管理员维护服务器的 Python、工作目录和可选私钥引用。启用统一占用后，已获准的环境共享服务器目录，经平台核验的单份运行配置可供多个环境使用。每台物理服务器同时只运行一个任务，其他任务等待当前占用释放。自有 GPU 的 `queue_root` 固定物理队列和锁目录，创建后保留原值。原两台 GPU 使用 `/home/oort/.local/state/vlstream-shared/v1`。

自有 GPU 可采用平台保存的 SSH 密码或执行端私钥引用。平台对密码、AutoDL Token 和执行历史版本使用 AES-256-GCM 加密，管理接口只返回配置状态，编辑留空保留原值，清除须显式选择。AutoDL 运行时 SSH 连接由同一实例的供应商接口提供，资源中维护固定主机信任、供应商身份和本方整机小时价。后端持久密钥须与加密数据一起迁移，缺失或错误密钥会明确报错。执行目录的应用凭据、解密数据和用户输入凭据均从调试展示中隐藏。

## VLS 读取与任务恢复

算力目录与模型中心直接使用同一个 `vls.model-hub` 配置对象，地址和应用身份由 `VLS_MODEL_HUB_BASE_URL`、`VLS_MODEL_HUB_APP_ID` 和 `VLS_MODEL_HUB_SECRET_KEY` 配置。请求地址为该根地址追加 `/compute/v1/executionCatalog`。新版 Deployment 验证应用身份后返回执行环境。统一占用开启后返回共用目录和对应运行版本，开启前按应用所属环境返回目录。仍只返回资源和历史版本的旧接口也需通过服务应用鉴权。VLS 在已启用、已发布的记录只有一个共同执行环境时，读取该环境的运行配置和对应历史版本。新旧接口都无需手填 VLS 执行环境。已取得新版授权后拒绝退回旧格式。手填的 `shared-pool.environment-id` 仅供历史 YAML 供给使用。默认每 15 秒刷新，目录有效期默认 60 秒，快照默认保存到 `${user.dir}/data/security/compute-catalog.snapshot`。

WorkUp 2443 是现有公司 GPU 的主要使用环境，本地仅临时连接供开发调试。保留目录内既有 `localhost` 标识以便历史任务恢复。旧目录只认证服务身份，无法用返回内容证明不同应用各自获准的环境。启用新版授权时，正式和本地使用各自的服务应用身份，deployment 返回各自获准的执行目录。分配给其他应用的新服务器，在能力中心「算力」中绑定该应用对应的唯一环境。

WorkUp 2443 的官方 RTX 6000D 固定价格为 13 元／整实例小时。有效执行目录仍是实际开机报价的价格来源。目录暂不可用时，仅该实例的历史展示卡沿用 13 元标价，卡片的租用条件继续由服务端单独校验。

### 由 Deployment 统一记录跨环境占用

统一占用启用后，获准的服务应用读取同一批公司服务器，使用各自的应用身份领取服务器。免费训练、智能标注和检测任务确认远端退出、回存及主机锁释放后才能回调。付费实例在原开机和冻结前领取，停机、结算和工作区清理完成后释放。原付费归档需要恢复时，原付款人按现有流程续用同一个占用。超时、进程状态未知或未收到可靠回执时保持占用。回调可以重试，迟到的旧回调不能释放下一笔占用。

Deployment 使用服务端 `compute.LeaseCoordinationEnabled` 启用协调。切换前确认全部参与环境已运行支持该能力的 VLS、迁移已完成、旧任务和旧付费占用已收尾，避免旧调度器绕过中心领取。当前 2443 旧目录兼容修复可单独更新，开启统一占用需同步更新 Deployment。

目录刷新原子替换资源，身份一致时保留已有探测证据。新任务冻结执行版本，准入与目录更新通过数据库锁协调，并读取已提交活动任务的当前身份。地址、账户、凭据、运行路径或其他执行信息改变时，活动任务继续使用原历史版本，切换完成后允许后续任务使用新目标。停用、撤下和逻辑删除阻止新准入，原任务仍可按冻结身份停止和归档。已接受订单沿原报价结算，后续报价读取有效平台价格。

目录失联会保留加密恢复快照并停止新准入。服务恢复后先按历史版本接管已有任务，取得新的目录确认后再接受新任务。恢复快照加密依赖 VLS 原有算力密钥，原密钥和凭据持久化路径继续沿用。

共享 deployment 地址存在时使用统一目录，目标服务须具备目录接口、应用授权、已迁移的资源和匹配的执行环境。`application-compute-legacy.yml` 保留原三台 `company-resources.resources` 的身份、价格和部署配置引用，仅在共享地址为空时用于兼容已有配置。目录失联仍拒绝新准入，不自动回退旧配置。资源展示不替代执行端 SSH 身份和真实环境检查。VLS 私人节点继续按原本人和租户规则管理，旧远程执行器继续读取 `vlstream.ssh`。接口字段、发布及权限约定见相邻服务的[能力目录接口文档](../../apaas-deployment-service/docs/capability-catalog-api.md)。
