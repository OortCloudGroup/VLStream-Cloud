# VLS 训练算力与 NewAPI 个人余额结算需求

版本：实现需求 v3｜日期：2026-10-10｜交付对象：NewAPI 中转站及 VLS 后端同事

中转站可以立即开发个人余额、权威额度换算、原子幂等扣款、查单和账务纠错接口，不必等待存储产品设计。首版只销售训练算力；GPU 磁盘属于平台工作空间，停机后的磁盘成本由平台承担。本文是待实现契约，建议路径与示例不表示现有 NewAPI 已支持，也不表示 VLS 已完成真实接入。

## 1 已确定业务边界

- 统一 SSO，VLS 用户就是 NewAPI 用户，沿用可信稳定主体；仅扣个人余额，不建设租户钱包或独立账户映射。
- accessToken 用于认证，额度是余额单位；后台计费不依赖浏览器短期 token 或用户页面在线。
- 算力实例独占，一实例可包含多张 GPU；按供应商整实例小时成本计费一次，不再乘 GPU 数量。
- 用户 GPU 费用＝整实例小时成本 × 2 × 实际计费秒数 ÷ 3600。从成功开机计至实际停机，闲置仍收费，不凑整小时。
- 供应商计算费最低消费与按秒计量的差额由 VLS 承担，不向用户补收最低时长或最低计算费。
- 首版不销售持久盘，不向用户收取存储费、存储续费或存储欠费。磁盘及其停机后费用计入平台成本。
- VLS 不提供故障赔付；错误扣款、重复扣款和误收未发生费用必须冲正，账务纠错不属于故障赔付。
- VLS 不提供人工服务，不设置欠费人工处理、客服赔付或人工兜底队列作为产品流程。
- 公共算力池对所有租户可见；租用权限、训练数据、产物与任务控制严格按实际用户隔离，不开放其他用户的数据或控制权限。
- 目标供应商方案为新建 AutoDL Pro 实例，不迁移旧实例；当前无真实购买授权。供应商操作由 VLS 实现，中转站不负责购买、启停或清理 GPU。

## 2 分工与实施阶段

第一阶段，中转站立即实现第 3 至第 6 节的稳定资金接口。VLS 提供用户主体、唯一业务编号和整数扣款额度；中转站不计算 GPU 价格、不理解训练文件，也不等待磁盘商品设计。

第二阶段，补齐第 7 节的资金保护与 VLS 自动运行闭环。可以独立排期，但训练收费开售前必须完成冻结预留或经验证的等效资金保护，以及余额不足自动停机、结果未知恢复和账务对账；第一阶段接口完成不等于已经具备开售条件。

- NewAPI 负责：权威个人余额与兑换规则、原子资金操作、业务去重、查单、纠错退款和资金流水。
- VLS 负责：SSO 验证、资源独占、供应商价格与状态核验、计量计算、持续扣费、自动停机、产物归档和安全复用。
- 不伪造模型请求或 token 用量抵扣算力费用；新增独立业务类型 `GPU_COMPUTE`。
- GPU 运行账单与供应商实际总成本分开记录。工作盘、最低费差额和平台维护任务不得混入用户计算账单。

## 3 第一阶段必须提供的接口

统一建议前缀：`/api/v1/external-billing`。仅供受限 VLS 后端调用，前端不直接持有结算服务凭据。

| 方法与建议路径 | 必须实现的语义 |
| --- | --- |
| `GET /config` | 最小额度单位、结算币种、权威换算比例、规则版本、有效时间及服务端时间 |
| `GET /users/{user_id}/balance` | 账面余额、现有冻结、实际可用余额和余额版本 |
| `POST /charges` | 原子扣取指定整数额度，落资金流水并保存幂等结果；不足时整体拒绝 |
| `GET /charges/by-reference/{merchant_charge_id}` | 按商户唯一扣款编号查原单，返回状态、金额、用户、业务引用及资金流水 |
| `GET /operations/by-key/{idempotency_key}` | 查询写操作的处理中、成功、明确拒绝或不存在状态 |
| `POST /charges/{charge_id}/refunds` | 引用原扣款进行同用户原余额的账务纠错退款，支持部分冲正 |
| `GET /ledger?from=...&to=...&cursor=...` | 按商户与时间游标读取扣款、退款及已启用冻结操作的审计流水 |

- `available_quota = balance_quota - held_quota`；所有扣款必须使用真实可用余额，即使先查余额足够，提交时仍要原子检查。
- 暂未启用冻结时，`held_quota` 可以为零；如果 NewAPI 已存在其他冻结，必须扣除，不能假定为零。
- 同一钱包的模型调用与新业务必须共用并发安全扣费路径，禁止读余额后分别无条件写回。
- `merchant_charge_id` 标识一个不可变计费区间；`usage_session_id` 关联一次 GPU 开机周期，均由 VLS 持久化生成。
- 查单与流水只能返回已授权商户及用户范围；任何用户、商户归属不得在扣款后修改。

## 4 字段与占位示例

金额统一用最小额度单位的非负整数字符串，避免 JavaScript 大整数丢失。价格未知时不能填默认金额；以下占位符不是真实用户、金额或凭据。

权威配置返回：
```json
{"quota_unit":"<最小额度单位>","settlement_currency":"<ISO币种>","quota_per_currency_unit":{"numerator":"<正整数>","denominator":"<正整数>"},"conversion_version":"<版本>","effective_at":"<UTC时间>","valid_until":"<UTC时间>"}
```

扣款请求，必须携带 `Idempotency-Key`：
```json
{"merchant_id":"<VLS商户标识>","request_id":"<请求标识>","merchant_charge_id":"<计费区间唯一编号>","user_id":"<可信SSO主体>","business_type":"GPU_COMPUTE","usage_session_id":"<开机周期ID>","charge_quota":"<整数额度>","metering_ref":"<不可变计量记录ID>","price_snapshot_id":"<价格快照ID>","conversion_version":"<兑换版本>"}
```

扣款成功响应：
```json
{"operation_id":"<操作ID>","status":"SUCCEEDED","charge_id":"<扣款单ID>","ledger_entry_id":"<资金流水ID>","charged_quota":"<实际整数扣款>","available_quota":"<扣款后可用余额>","balance_version":"<新余额版本>"}
```

- 纠错退款请求使用 `merchant_refund_id`、`original_ledger_entry_id`、`refund_quota`、`reason_code` 和新的幂等键；原因限经核实的账务错误等情形，不设置故障赔付原因码。
- 所有写操作返回稳定 `operation_id`，日志关联 `request_id`；幂等身份不依赖可过期的 HTTP 会话。
- 账单展示至少包括用户、实例、开机周期、UTC 计费起止、秒数、整实例费率、2 倍系数、兑换版本及实际扣款额度。

## 5 原子性 幂等与未知结果

- 一个事务内完成可用余额校验、扣款、资金流水、业务去重和幂等结果；失败不允许任何局部资金变化，也不允许负余额。
- 幂等键按商户隔离并绑定规范化请求摘要。同键同内容返回原结果，同键不同内容明确报冲突。
- `(merchant_id, merchant_charge_id)` 另设成功扣款唯一约束，且业务编号绑定不可变用户、金额和计量区间，避免更换幂等键重复扣款。
- 同一区间最多一笔成功扣款；重复、乱序、进程重启或响应丢失不能产生第二笔消费。
- 查询必须区分 `PROCESSING`、`SUCCEEDED`、`REJECTED`、`NOT_FOUND`；明确拒绝表示该操作未发生资金变化。
- 超时、断连、5xx 视为未知，先按原幂等键和业务编号查单。处理中继续查；成功恢复本地状态；查无记录时仅以原键、原请求重试。
- 未知结果不能换单重扣或直接退款。余额不足明确拒绝后，才可在满足资金条件时新建重试操作；原业务编号和成功去重规则保持不变。
- 错误至少区分 `INSUFFICIENT_AVAILABLE_QUOTA`、`IDEMPOTENCY_CONFLICT`、`BUSINESS_REFERENCE_CONFLICT`、`UNAUTHORIZED`、`INVALID_REQUEST`、`RETRYABLE_UNAVAILABLE`。
- 退款引用真实成功扣款，累计退款不得超过原实际扣款；退款去重、限额检查和余额增加在同一事务内完成。
- 资金流水不可原地改写，纠错使用关联冲正；幂等结果和业务去重索引至少与对应账务记录同寿命。
- 流水保存商户、用户、操作、业务引用、原扣款、金额、余额前后值和服务端时间；支持与 VLS 计量记录逐条对账。

## 6 身份与额度精度

- 复用现有可信 SSO 验证机制。JWT 校验签名、签发方、受众和有效期；opaque token 由受信服务校验，取得稳定主体。
- 不接受浏览器任意指定付款用户。NewAPI 核验可信主体或受限服务提供的可验证身份断言，并落实用户归属检查。
- 后台使用可持续运行且可撤销的受限服务身份，权限仅覆盖指定商户的资金接口；不使用管理员全权限令牌。
- 本文不生成、读取或配置任何实际凭据；服务凭据和用户 token 不进入日志、示例或账单。
- 额度换算必须以 NewAPI 权威返回为准，不擅定“1 元对应多少额度”。价格与汇率未知、失效且无有效历史适用快照时不得扣费。
- VLS 使用精确十进制或有理数计算；累计有效时长后计算增量，禁止每轮向上取整秒数或用二进制浮点累计金额。
- 整数额度以下余数按用户持久化累计，跨扣费周期和开停机保留；余数分配、计量游标和待扣指令在同一事务生成。
- 未决扣款保留其余数分配并复用原指令，不能再次参与分配；用户下多实例的余数分配应串行化或等效原子处理。
- 保存供应商报价、价格生效区间、币种换算与额度兑换版本；变更只按已明示规则影响未来用量，不改历史已确认区间。
- AutoDL 普通实例的锁价规则不能直接套到 Pro；VLS 按实际产品核验规则并保存分段快照，中转站只处理确定的整数额度。

## 7 独立阶段的资金保护与开售条件

本节不阻塞第一阶段开发，但不能仅靠定时“先查余额再扣费”宣称训练费用已有保障。

- 推荐新增开机周期的冻结预留、扣费时消耗冻结、运行中补足，以及最终结算后释放余款；冻结金额仍在同一个人钱包内。
- 冻结接口可以独立交付，但一旦启用，现有模型消费与其他业务必须同样尊重冻结，不能绕过。
- 推荐 VLS 初始预留覆盖 1 小时计算费；不预留用户存储费。停机安全预算至少 5 分钟，计入预留窗口并按实测耗时调大。
- 预计可支付运行时长下穿 2 小时、30 分钟时提醒，持续同状态抑制重复通知；这些是 VLS 可配置默认，尚未经真实供应商接入验证。
- 不能覆盖停机预算、无法确认扣费结果或资金服务持续不可用时，禁止新增租用并自动进入安全停机，不等待人工。
- 供应商支持幂等键时复用原键；不支持时先查状态，再安全重试。仅收到停机请求不代表已停机，必须持续确认实际状态。
- 记录用户计费截止与供应商实际停收时点；普通停止状态不一定终止上游计算费，VLS 必须核验对应产品模式，不能静默延长用户账单。
- 如暂不实现冻结，必须先交付并验收等效资金保护方案，明确并发消费和停机延迟的成本风险，不能让 NewAPI 透支填补。
- 中转站基础接口可先通过模拟数据联调；真实训练收费开售还须通过资源独占、后台持续计量、失败恢复、停机与对账验收。

## 8 VLS 训练工作空间与未完成环节

以下全部由 VLS 负责，不扩展成用户存储商品，也不要求中转站实现供应商操作或文件服务。

- MinIO 保存权威训练输入与应归档产物，GPU 本地磁盘作为可重建的平台工作空间；新任务可从已校验输入重建所需环境和数据。
- 数据路径、对象访问和任务控制绑定可信 `user_id` 与训练任务，禁止因公共算力池可见而暴露其他用户文件、日志、产物或访问凭据。
- 训练产物回传 MinIO 后，校验约定产物清单、对象存在性、大小及校验和；全部通过才标记 `READY`，其后才可清理工作空间。
- 清理后验证无前一用户数据、临时凭据和残留进程，再解除独占锁并复用；仅训练进程退出不等于可以交给下一用户。
- 回传或校验失败时保留数据、隔离实例，后台自动重试并受停机预算约束；未达到 `READY` 不清理、不向下一用户分配，不依赖人工兜底。
- 平台清理、维护或修复性补传不得冒用用户身份新增计算扣款；对应支出单独记入平台成本。
- 当前完整日志、checkpoint 等尚未全部归档，不承诺断点续训、任意历史状态恢复或全量工作空间备份；`READY` 仅表示约定产物清单已经校验。
- AutoDL Pro 新实例采购、真实生命周期适配、完整自动恢复及安全复用闭环仍需实施验证；不迁移旧实例，不据本文执行真实购买。
- 不提供人工服务不等于隐去失败：自动流程无法完成时，用户看到准确任务状态和可执行下一步；资源保持隔离，不能假报完成或继续不明收费。

## 9 验收清单

中转站第一阶段：

- [ ] 同一 SSO 用户关联正确个人余额；伪造用户、跨用户和跨商户请求被拒绝。
- [ ] 权威兑换比例与版本可查；整数额度和大整数全链路不丢精度。
- [ ] 模型调用、多 GPU 实例并发扣款不超花余额，不覆盖彼此资金变化。
- [ ] 同单重复请求、换键重试、断连、提交后崩溃与乱序响应均只产生一笔成功扣款。
- [ ] 原单可查询恢复，未知结果不换单重扣；同键异参和同业务编号异内容明确报冲突。
- [ ] 部分及全额纠错退款不超过原扣款，不重复加余额，保留完整原流水关联。
- [ ] 后台无需浏览器在线即可认证和结算，受限服务身份可审计与撤销。

VLS 收费开售前：

- [ ] 整实例只计一次，成功开机到实际停机按秒累计，闲置收费，失败启动无 GPU 费。
- [ ] 不产生个人存储账单；计算费最低消费差额、工作盘和平台维护成本与用户账单分离。
- [ ] 资金保护、停机预算、自动失败恢复和三方对账通过真实场景验证，不依赖人工处理。
- [ ] 不提供故障赔付，同时正确执行误扣与重复扣款冲正。
- [ ] 公共资源可见但数据与控制隔离；产物回传校验 `READY`、安全清理、再分配形成闭环。
- [ ] 明示当前归档范围与无断点续训承诺，未完成能力不在页面宣称已支持。
