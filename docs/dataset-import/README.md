# 数据集管理与数据来源

用户入口：算法仓库 → 算法训练平台 → **数据集管理**（`/data-management`）。
页面顶部切换“数据集”和“数据来源”。不再要求用户先建立项目；已有记录、样本、标签、标注及版本 ID 保留。
底层兼容接口 `/vlsData/projects` 暂保留，页面使用 `dataset` 查询参数，也兼容旧的 `project` 链接。

## 本轮范围

| 能力 | 实现范围 |
| --- | --- |
| 本地导入 | 图片、视频、文件夹及ZIP；8 MiB分片、完整SHA-256、暂停/恢复、刷新后重新选文件续传、后台导入与记录 |
| 外部S3 | 自定义Endpoint/Region/Bucket/Prefix及只读凭据、匿名Bucket、目录分页查看、单文件/ZIP或目录导入 |
| 公开数据集 | 公开HTTP(S)图片、视频、ZIP；GitHub、Hugging Face、Gitee的blob文件页转换为下载链接；GitCode等服务可使用有效直链 |
| 标注格式 | 无标注媒体；VLS归档的`vls-samples.json`；YOLO矩形检测ZIP的`data.yaml`/`dataset.yaml`、images和labels |
| 自有云盘 | TODO，等待公司云盘接口；需求见[对接文档](COMPANY_DRIVE_INTEGRATION.md) |
| 平台已有数据集 | TODO，按用户要求暂不开发直接导入 |
| 摄像头采集 | TODO，按用户要求暂不开发采集入库 |

百度网盘、官方公共数据集库、云服务数据回流均不在本轮范围，也不提供对应入口。
未新增数据清洗/增强流程。导入时校验格式和完整性；质量审核入口、统计、字段和相关说明从前端隐藏，
后台能力及历史质量记录保留。TODO能力只保留在开发文档，不显示在来源页或导入选项中。
数据集管理中新建类型只展示物体检测；历史分类/分割类型保持只读，保留已有文件和版本管理，
不展示尚无完整实现的在线标注/训练生成操作。YOLO检测框仅对物体检测数据集开放。
公开来源在页面命名为“公开文件链接”，以区分实际文件导入与未实现的整站数据集搜索/目录能力。
公开来源不会运行仓库脚本，暂不解析Parquet、TAR、COCO、LabelMe或受限/付费下载资源。

## 用户流程

视频导入后可通过“视频切图”按时间间隔生成图片，图片进入同一数据集供后续标注和划分，
详情可追溯来源视频及实际帧时间。参见[视频切图说明](VIDEO_FRAMES.md)。

1. 新建数据集，填写名称、编号、说明及现有标注类型；既有项目记录直接作为数据集使用。
2. 点击“导入样本”或流程图的导入入口，选择无标注/有标注及导入方式。
3. 本地选择文件或文件夹后点击“开始 / 继续上传”。文件校验在浏览器Worker中分块执行，避免占用主页面内存。
4. 上传分片由VLS校验后转存到当前默认MinIO/S3；任务持久保存存储配置键、文件大小、摘要及已确认分片。
   网络失败自动尝试重传分片，暂停或刷新不丢失已确认分片；重新选择内容相同的文件即可恢复。
5. 全部分片完成后校验分片序号与长度，再完成S3合并，创建后台解析任务。上传100%不表示已导入成功。
6. 后台从固定对象读取，检查完整摘要和大小，流式解包并校验媒体/标注，写入当前存储及样本数据库。
   同一数据集内按SHA-256去重；已有样本/标注不因重复文件被覆盖。ZIP登记在一个事务内完成，失败回滚并清理本批暂存对象。
7. “导入记录”显示排队、解析/导入、完成、部分成功或失败，可查看结果和重试；关闭页面后排队任务仍继续。
8. 外部S3或公开链接从“数据来源”配置，点击来源“导入”选择目标数据集后创建后台任务。
   S3仅列举和读取外部对象，不修改来源Bucket；导入后的内容和标注独立保存在VLS。

## 上传大小与恢复边界

- 单个文件（含ZIP）≤**4 GiB = 4,294,967,296字节**是本轮验收边界；超过4 GiB继续尝试，默认文件上限16 GiB，可配置。
- 同一文件恢复依据完整SHA-256和字节数，不仅依据文件名；服务重启后任务与分片记录仍存在。
- 浏览器重开后需要用户重新选择原文件，不保存任意本地路径访问权限，也不宣称可在浏览器关闭后继续上传尚未发送的内容。
- 暂存上传默认7天后清理。完成任务保留结果，上传暂存对象可清理；已导入媒体不会因此删除。
- 兼容格式为JPG/JPEG、PNG、BMP、MP4、MOV、ZIP；图片仍有4000万像素上限，视频仅验证容器结构，内容质量由人工播放确认。
- ZIP支持ZIP64，默认解压总量32 GiB、最多30000文件/10000媒体样本，单数据集最多10000样本。
  4 GiB压缩文件不等于4 GiB解压数据；超出配额、磁盘不足或文件损坏会明确失败。
- 单次本地选择最多500文件，可分批继续；S3目录递归按Prefix列举，超过10000支持文件需缩小范围。
- S3带标注导入请选择包含完整标注的ZIP对象；目录批量导入当前面向无标注媒体/归档。
- 既有ZIP导出大小上限仍为1 GiB，此次4 GiB保证针对上传与导入，不扩展旧导出接口。

## 配置和部署

新增迁移：`V1_2_0_013__dataset_sources_resumable_imports.sql`，包含来源、导入任务、上传分片三张表。
后端更新启动时由Flyway执行；旧迁移不能修改或重跑。前端与后端需要一起更新，单独更新前端会请求尚不存在的接口。

| 配置 | 默认 | 用途 |
| --- | --- | --- |
| `VLS_DATASET_MAX_FILE_BYTES` | 17179869184 | 单个来源文件或上传文件上限，最低支持4 GiB |
| `VLS_DATASET_MAX_UNPACKED_BYTES` | 34359738368 | ZIP解压后总大小限额 |
| `VLS_DATASET_ALLOW_PRIVATE_S3` | false | 允许管理员明确配置的内网S3来源；公开下载仍拒绝内网地址 |
| `VLS_DATASET_IMPORT_SCAN_MS` | 3000 | 后台扫描任务间隔 |
| `vlstream.data-management.temp-directory` | 现有`java.io.tmpdir/vls-data` | 大文件落盘与解包暂存，沿用当前路径配置 |

上传分片为8 MiB，请确保反向代理允许略大于8 MiB的multipart请求，超时覆盖一片传输；无需让单个请求通过4 GiB。
当前实现采用同源后端分片代理，浏览器无需新增MinIO CORS配置，也不直接持有S3密钥。
当前存储读取沿用`OssFactory`默认配置；上传期间固定配置键与Bucket，更换Bucket时拒绝拼接到新存储。

来源凭据使用现有服务端加密能力保存，不出现在接口结果或浏览器持久存储中；复用服务端配置的加密密钥，
部署时应覆盖仓库默认密钥并保持一致。来源请求发生错误时只输出状态，不打印带凭据的请求对象。
S3默认仅允许公网地址，启用内网来源时仍拒绝链路本地/元数据服务地址。公开HTTP下载会校验每次DNS解析和重定向，拒绝内网、非HTTP和HTTPS降级。

后台工作进程轮询数据库任务，跨租户扫描仅用于领取任务；实际处理和写入恢复任务所属租户，
通过工作进程ID和心跳约束状态更新，10分钟失去心跳的任务允许重试接管。

## 运行验证说明

本轮使用现有运行中的本地MinIO服务，在独立`vls-dataset-import-check`测试Bucket和专用MySQL库中验证，
不把测试表或数据写入用户业务库；所有生成文件保存在项目`codex/dataset-import-v2`。

- 精确4 GiB的合成MP4容器通过512个8 MiB分片上传，中途128片后重新初始化返回同一任务及全部已确认分片；
  完成后S3对象大小、最终样本大小与SHA-256一致。该文件用于验证传输和容器长度边界，不是可播放的真实视频内容。
- 浏览器对256 MiB合成容器在17片后暂停、刷新、重新选文件续传，最终导入一个样本，未建立重复上传任务。
- S3目录列举/导入、加密凭据不回显、分片损坏拒绝、跨租户拒绝、YOLO/VLS标注恢复通过集成测试。
- 公开链接实测：Hugging Face `huggingface/cats-image` 中`cats_image.jpeg`，173131字节、640×480，
  通过后台下载和入库，页面显示来源及导入完成。没有把此图片上架为平台官方数据集。

最终构建、完整测试、ZIP64额外边界与清理结果见本次交付的`codex/dataset-import-v2/验收结果.md`。
本轮未触发远端GPU训练，也未把上传能力验证当作模型训练完成证据。
