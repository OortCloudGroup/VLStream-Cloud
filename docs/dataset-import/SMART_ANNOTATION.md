# 四类智能标注与训练

> 2026-09-22 四类扩展：本节替代下文初版中“仅物体检测”的限制。下文保留初版操作背景，最新实现以本节及源码为准。

| 类型 | 正式标注 | 训练 |
| --- | --- | --- |
| 图像分类 | 每图一个类别 | YOLO分类，按类别索引目录组织，产物保存实际类别名 |
| 物体检测 | 检测框和类别 | YOLO检测TXT，保留原有检测流程 |
| 实例分割 | 每对象独立PNG掩膜，保留孔洞/分离区域/重叠对象 | 自定义YOLO数据加载器直接送入像素掩膜损失 |
| 语义分割 | 每像素恰好一个类别 | DeepLabV3 ResNet50，原图大小类别索引PNG |

四类均支持主动学习和指定模型。分割编辑器提供画笔、橡皮、撤销；语义分割提供未归类区域填充。分类选择整图类别。已有不兼容标注替换前保存版本。人工编辑使用版本摘要检查并发冲突。

数据集管理现在开放四类创建、编辑、训练目录生成；分类/分割从`/dataset-annotation`进入人工标注，检测沿用原编辑器。正式训练按四类匹配基础模型及数据格式，生成PT并允许保存到模型列表、供后续智能标注使用。分类和语义分割的主动学习门槛按每类覆盖图片数，检测/实例按实例数。

新增“一键确认剩余预测”，必须用户显式点击后才启动。后台逐图事务和持久游标支持继续处理；低置信度、未知标签、空结果、并发冲突等保留待确认并显示原因。状态增加`CONFIRMING`。完成任务仍只保存确认过的结果；用户可先执行全量确认，再完成任务。

系统基础模型为YOLOv8检测/分类/实例分割及Torchvision DeepLabV3语义分割。首次使用需下载官方权重或预置缓存。语义分割自有PT须为平台生成的DeepLabV3检查点，不能任意替换。代码参考Ultralytics 8.3.240、PyTorch 2.5.1和Torchvision 0.20.1；正式GPU容器依赖需现场核对。

四类共用现有GPU队列。非检测正式模型只完成PT并进入模型保存链路，不自动套用检测专用的ONNX/OM/RKNN转换；设备适配不在本次范围。新迁移`V1_2_0_022__four_type_annotation_payloads.sql`接续021，扩展任务类型、掩膜容量、进度和后台确认字段。

单掩膜最多8MiB、单图载荷最多24MiB、最多4000万像素。单轮远端结果文件目前限制64MiB，超限任务明确失败，应拆分数据集；不把无效或过大结果计为成功。

本轮证据位于`codex/smart-four/`。四类均通过真实CPU小型合成数据训练和推理，证明链路可执行，不代表业务精度。未部署正式服务、未执行业务库迁移、未在真实GPU上训练。

## 初版检测流程记录

入口：算法仓库 → 算法训练平台 → 智能标注，或数据集详情 → 智能标注。

## 两种模式

- **指定模型**：选择已有 PT 模型或主动学习成功轮次的模型，对当前未标注图片进行批量推理。预测框先进入待确认区；可逐图修改类别、移动框、调整坐标和大小、补框和删除框，再确认保存；也可以显式确认本页符合条件的结果。
- **主动学习**：用数据集已确认标注训练本轮检测模型，对其余图片推理，优先展示平均预测置信度较低或没有检测框的图片。确认或跳过本轮难例后，且本轮至少确认一张图片，可再次训练下一轮。未确认预测不作为训练标签。

当前只支持目标检测；权重通过 Ultralytics 加载后必须识别为 `detect`。基础算法权重仅用于主动学习；指定模型使用已训练模型或成功的主动学习轮次。模型未知类别不按数字下标猜测对应关系：同名标签自动匹配，未匹配类别需要用户在确认页选择标签。

首次主动学习默认要求每类至少 10 个标注框、至少 101 张可用未标注图片，最多 4 轮。指定模型至少需要 1 张可用未标注图片。这些门槛参考 EasyDL，属于工作流条件，并不保证达到某个模型精度或标注节省比例。

```yaml
vlstream:
  smart-annotation:
    min-boxes-per-label: 10
    min-unlabeled-images: 101
    max-rounds: 4
```

每轮训练次数默认为 10，可选 1–100；难例数量默认为 50，可选 1–500；预测阈值为 0.05–0.95。推理和训练当前固定使用 640 输入尺寸；主动学习训练 batch=4，并复用训练容器的 workers 设置。难例排序是置信度启发式，不是百度私有算法的实现，也不等于真实错误率。

## 状态与数据归属

任务按 `QUEUED → PREPARING → RUNNING → REVIEW → COMPLETED` 转移。失败进入 `FAILED`，可重试同一轮输入；重试会创建全新的远端尝试目录和容器名。取消排队或运行中的任务先进入 `CANCEL_REQUESTED`，调度器停止本任务后进入 `CANCELLED`；已确认标注始终保留。

任务、轮次、预测分别存储在 `vls_smart_annotation_task`、`vls_smart_annotation_round`、`vls_smart_annotation_candidate`。每轮引用既有数据集版本快照，保留模型 SHA-256 和模型路径。图片仍由当前对象存储持有，远端执行读取稳定对象键，不下载浏览器签名链接。

确认是同一数据库事务内的操作：校验租户、数据集、当前轮次、图片内容标识、标签归属和坐标，拒绝覆盖已被人工标注的图片，然后调用原标注保存服务，更新图片进度并使旧训练目录失效。重复确认不会重复写入。批量确认中任一图片发生冲突时整批回滚。完成任务保存结果版本；未确认预测不会自动成为正式标注。

无目标预测允许手工补框或跳过。跳过不会生成空的正式标注，也不会计入已有“有标注图片”统计；本次不扩展负样本训练能力。视频仍需先切图。

创建与轮次推进使用原数据集锁。进行中的智能标注任务会阻止删除数据集；用户先结束或取消任务。数据集的一般人工编辑仍允许，确认时检查冲突。训练/验证划分尊重已有验证集，并检查相同内容不可跨集合。

## GPU 执行与上线

新增 `smart_annotation` 容器类型，复用 `GpuTrainingSchedulerService` 的持久 FIFO 和整卡独占策略，与正式训练共享队列。智能标注完成不会触发正式训练模型发布或 ONNX/OM 转换。沿用现有全局 SSH 连接、容器镜像和挂载配置。

执行文件位于 `${vlstream.training-container.host-data-dir}/vls-smart-annotation/<taskId>/<roundId>_<attempt>/`，包含冻结图片、训练标签、脚本、日志、模型与结果。模型必须位于现有容器数据挂载目录内。路径不使用用户提交的任意命令；取消仅针对该轮容器名。源 PT 权重复制到本轮独立目录后才加载。

上线需要应用 Flyway `V1_2_0_021__smart_annotation.sql`，更新后端并重启对应 JVM，同时更新前端。容器需具备现有 Conda Python、Ultralytics、PyTorch 和 CUDA 环境；主动学习使用的基础权重必须存在。当前单实例调度架构保持不变，不新增跨 JVM 分布式 GPU 调度能力。

接口前缀 `/vlsData/smart-annotation`，提供任务列表、创建、详情、候选模型/标签、预测分页、单图确认、批量确认、下一轮、完成、重试、取消和日志。客户端 ID 一律按字符串处理。

## 验证边界

验证记录与临时产物位于仓库根目录 `codex/smart-annotation/`。Java 8 单元及隔离 MySQL 测试覆盖正式标注写入/进度、版本冻结、训练目录失效、重复确认、跨租户拒绝、整批回滚、主动学习下一轮、取消状态及 GPU 任务类型隔离。

浏览器验收使用生产 Vue 页面、生产控制器和服务、隔离 MySQL、测试图片以及合成预测；GPU 执行由测试替身隔离。合成预测不能证明真实模型精度。业务库迁移、正式服务更新和真实 GPU 的训练/推理验收需在目标环境另行验证。

参考：[EasyData 图像智能标注](https://ai.baidu.com/ai-doc/EasyData/rk9jovuv4)，以及用户提供的 EasyDL 控制台。复用了两种模式和人工确认流程，未接入百度收费接口。
